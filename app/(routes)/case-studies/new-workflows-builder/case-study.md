# New Workflows Builder: MVP Strategy to Visual Design

## The Challenge
The existing Campaign Builder provided users with a linear, vertical workflow system following a step-by-step "this then that" layout. While functional for basic automation sequences, this approach limited users to simple, sequential workflows without flexibility for complex decision-making or branching logic.

The Campaign Builder was transformed into a robust Workflows Builder. This multi-branch logic system enables complex automations with conditional decision points and branching paths. This evolution allowed users to create automation sequences that adapt and respond to different conditions and user behaviors based on dynamic criteria.

To validate this concept and identify opportunities, a simple, low-fidelity MVP was created and tested with real AWeber users. This intentional approach provided valuable insights that would guide the development of a more refined workflow experience.

## Observations and Insights

The decision to begin with a simple, low-fidelity MVP proved instrumental in shaping the final visual design approach. This methodology provided critical advantages that informed the overall direction:

### The Value of Early Validation
By launching with minimal visual polish, user attention focused on core functionality rather than surface-level design elements. This approach revealed authentic user behavior patterns and genuine pain points that might have been obscured by polished interfaces.

Real user interactions with the MVP uncovered:
- Which workflow steps caused the most confusion without visual cues
- How users naturally expected to navigate between different action types
- Where cognitive load was highest in complex branching scenarios
- What information hierarchy users instinctively sought when building workflows

### Rapid Iteration Advantage
The MVP approach enabled faster deployment cycles and more responsive development. Rather than investing months in visual design before user validation, this approach allowed rapid feature deployment, functionality adjustments based on actual usage patterns, and validation of the fundamental workflow concept before visual investment.

### Foundation Before Polish
This methodology reinforced a critical principle: establishing solid functional foundations before investing in visual refinement. User feedback revealed that while the core workflow functionality was sound, the lack of visual hierarchy created unnecessary cognitive burden.

The insights gathered during the MVP phase directly informed the visual design priorities:
- Color coding emerged as the most requested feature for quick step identification
- Background contrast became essential for workflow readability
- Visual consistency across step types was crucial for user confidence

This validation-first approach ensured that visual design decisions were grounded in real user needs rather than assumptions, leading to the targeted color-coding and visual hierarchy solutions implemented.

## Solution
Several small but impactful changes were implemented to the visual design of Workflows, with a primary focus on improving how information is presented and creating a clear visual hierarchy.

### Color-Coded System
Each workflow step now features a strategic color-coding system that immediately identifies its action:
- **Purple** for triggers and starters
- **Blue** for standard actions 
- **Grey** for waits
- **Green** for branched logic

This color language creates an immediately recognizable visual hierarchy that helps users quickly understand the flow and purpose of each step in their automation.

### Enhanced Background Design
The background has been updated to a light blue and paired with a subtle pattern to create more effective contrast between the step cards and canvas. This improved background design enhances readability and helps the color-coded steps stand out more prominently within the workspace.

### Redesigned Step Cards
The entire series of step cards were redesigned with improved information presentation, making each workflow component more visually distinct and easier to interact with.

**Updated Components:**
- **Starter Step**: Redesigned with improved visual hierarchy and clearer action indicators
- **Add Step**: Enhanced interface for adding new workflow components
- **Send Message Step**: Improved layout for message configuration
- **Tag Step**: Better visual organization for tagging actions
- **Wait Step**: Clearer representation of timing controls
- **Check Feed Step**: Enhanced interface for feed monitoring
- **Split Path Step**: Improved branching logic visualization

**Enhanced User Experience:**
- **Scrolling Guardrails**: Added navigation aids to help users navigate complex workflows
- **Improved Contrast**: Better visual separation between elements
- **Consistent Visual Language**: Unified design system across all workflow components

## Outcomes and Impact
The three-phase approach of MVP validation, user learning, and targeted visual improvements delivered a comprehensive transformation. By starting with functional validation before visual polish, design decisions addressed real user needs rather than assumptions.

**Key Benefits:**
- **Immediate Recognition**: Users quickly identify different workflow step types
- **Enhanced Usability**: Complex workflow relationships become immediately understandable
- **Scalable Design System**: Visual language extends to other workflow experience areas
- **Improved Workflow Creation**: Users more efficiently build and modify automation sequences

## Reflections & Future Paths
The MVP approach proved invaluable in validating the concept with real users before investing in visual polish. This iterative methodology enabled:

- Test core functionality with minimal investment
- Gather authentic user feedback early in the process
- Refine both functionality and visual design based on real usage patterns
- Create a foundation for future workflow experience enhancements

The established color language and visual hierarchy provide a strong foundation for expanding the workflow experience into other areas of the platform, ensuring consistency and familiarity as users interact with automation tools across different contexts.
